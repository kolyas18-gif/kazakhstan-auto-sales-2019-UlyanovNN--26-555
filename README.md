Период: январь–сентябрь 2019 года. Объект отдельного анализа: «Меркур Авто».

Репозиторий: [код и тетради проекта на GitHub](https://github.com/kolyas18-gif/kazakhstan-auto-sales-2019-UlyanovNN--26-555).

Для HTML-копий исходники кода доступны в той же папке проекта, но автоматический просмотр HTML в браузере среды был недоступен из-за запрета локальных file-адресов; графики проверены по PNG, документ — по страницам Word.

## Как воспроизвести

Распаковать весь комплект. Открыть терминал в папке `coursework` и использовать Python 3.12:

```bash
python -m pip install -r requirements.txt
python clean_data.py --input data/autokz2019_raw.csv --output data
python -m jupyter nbconvert --execute --to notebook --inplace 01_initial_review.ipynb
python -m jupyter nbconvert --execute --to notebook --inplace 02_cleaning.ipynb
python -m jupyter nbconvert --execute --to notebook --inplace 03_market_eda.ipynb
python -m jupyter nbconvert --execute --to notebook --inplace 04_mercur_analysis.ipynb
python verify_project.py
```

В Jupyter можно вместо команд выбрать Restart Kernel and Run All для каждой тетради в порядке 01–04. Тетради 03 и 04 требуют готовый очищенный файл; 04 также показывает таблицу чувствительности, сохранённую тетрадью 03. Все необходимые входные и производные файлы уже включены.

`build_notebooks.py`, `enrich_notebooks.py`, `execute_notebooks.py` и `build_report.py` — вспомогательные средства сборки комплекта. Для обычного просмотра они не нужны. Повторная сборка тетрадей удаляет их старые результаты; после неё требуется выполнение. `execute_notebooks.py` создаёт локальную конфигурацию ядра в `.jupyter`; стандартный nbconvert выше не зависит от путей среды автора.

## Формат итогового CSV

Кодировка UTF-8 с BOM; разделитель — запятая; десятичный знак — точка; дата — `YYYY-MM-DD`. Пропуски записаны пустыми полями. Это отличается от разделителей исходника и явно задаётся в коде чтения.

```python
from clean_data import read_clean
df = read_clean('data/autokz2019_clean.csv')
```

CSV не хранит сведения о типах `category` и `datetime`: функция выше восстанавливает их и выполняет проверки. Поля `quantity` и `manufacture_year` имеют тип Int64, `engine_l` — Float64; денежные поля — числовые.

Итоговая строка — группа с одинаковыми месяцем, компанией, характеристиками автомобиля, географией, ценой и признаком возврата. **Количество строк не равно продажам.** `source_records` показывает, сколько очищенных исходных записей вошло в группу; объёмы и суммы при объединении сохранены.

## Ключевые методические решения

1. Точные дубликаты удалены по всем 25 исходным полям согласно заданию. Без ID сделки нельзя доказать, что все совпадения — повторная загрузка. Тетрадь 03 показывает чувствительность: внутренний объём 51 955 без удаления и 34 725 после; доля «Меркур Авто» 1.251% и 1.135% соответственно.
2. Удаление ненужных полей отложено до восстановления значений из модификации и смещённых столбцов. Новые совпадения после удаления полей агрегированы, а не отброшены.
3. «Сегмент ЕПР» отсутствует буквально; в качестве дополнительного сегмента удалена «Сегментация Eng». Сохранены «Сегментация 2013» и «Класс 2013».
4. Шесть строк без количества вынесены в карантин. Неизвестные характеристики остальных строк оставлены пропусками. Нулевой объём ДВС — только электромобили, а не обозначение пропуска.
5. Возврат -1 и крупные партии не удалены. Средний чек на автомобиль рассчитан по положительным продажам, нетто-объёмы — с возвратом. Покупатель оптовых партий не установлен.
6. Экспорт сохранён в CSV, но исключён из основного сравнения внутреннего рынка.
7. Отсутствие Volkswagen у «Меркур Авто» с июня выявлено и в исходнике. Компании не объединялись без доказательств; причина разрыва не установлена.
8. Денежные значения — продажи в USD, не прибыль. Нельзя рассчитать маржу, рентабельность, конверсию или окупаемость без дополнительных данных.

## Сопутствующие материалы

- `data/autokz2019_raw.csv` — неизменённая копия предоставленного исходника.
- `data/clean_source_records.csv` — промежуточные очищенные записи до удаления служебных полей и агрегации; это **не файл для сдачи вместо итогового CSV**.
- `data/corrections.csv` — построчный журнал существенных восстановлений с номером строки источника.
- `data/quarantine.csv` — строки, исключённые из KPI из-за неизвестного количества.
- `data/unresolved_tokens.csv` — нераспознанные исходные значения категорий.
- `data/schema.csv`, `DATA_DICTIONARY.md` — схема и словарь итоговых полей.
- `data/cleaning_summary.json` — счётчики обработки и SHA-256 исходника.
- `tables/` — таблицы расчётов; `figures/` — 16 графиков.
- `verification_result.json` — результаты независимых числовых проверок и контроля тетрадей.
